# 云效工作项统计

## 目标

一键统计团队成员最近一个月的待办和已完成工作项数量，按人员分组生成统计报告，包含总览表和待办明细列表，并自动保存到 `_系统/日志/工作项统计/` 目录。运行过程中的临时文件统一写入笔记仓库 `.tmp/` 下本次运行独占的临时子目录；最终只保留 Markdown 报告，仅删除本次创建的 `$TMP_DIR`，除非用户明确要求保留。

## 笔记库路径约定

本技能位于 SYJC 工作区，配置和报告仍属于笔记库 `~/pp-note`。本文中的 `_系统/技能数据/`、`_系统/日志/` 和 `.tmp/` 路径均相对于笔记库；实际文件读写时必须加上笔记库根目录，不要在 SYJC 下创建这些目录。凭证与人员名单原位保留。

## 触发词

工作项统计、统计工作项、统计待办、人员待办统计、工作项月报、工作项周报、统计已完成

## 使用前与项目范围

先读 [公共说明](../manage-yunxiao-workitems/references/common.md)，统一工具、认证、组织、工作项查询参数、状态技术映射与分页。下文省略官方 MCP 客户端工具前缀。

按公共说明读取配置的 `YUNXIAO_PROJECT_IDS`，再合并笔记库 `_系统/技能数据/云效关注项目.md` 表格首列项目 ID，去重后逐项目查询。两个来源都为空时先询问，不扫描全组织。本技能使用下文独立的人员排除和统计口径。

## 执行流程

### 第 1 步：计算时间范围

根据用户指定的时间范围计算，默认为最近 1 个月。macOS/zsh：

**最近 1 个月**（默认）：

```bash
START="$(date -v-1m '+%Y-%m-%d 00:00:00')"
END="$(date '+%Y-%m-%d 23:59:59')"
```

**最近 1 周**：

```bash
START="$(date -v-1w '+%Y-%m-%d 00:00:00')"
END="$(date '+%Y-%m-%d 23:59:59')"
```

时间范围说明：
- 用户未指定时，默认使用"最近 1 个月"
- 用户提到"最近一周""本周""近 7 天"等，使用"最近 1 周"
- 用户提到"最近一个月""本月""近 30 天"等，使用"最近 1 个月"

### 临时文件目录约定

运行过程中产生的所有临时文件（查询原始 JSON、中间处理 JSON、`.err`/`.tmp` 等）统一放到**笔记仓库 `.tmp/` 下本次运行独占的临时子目录**，**不要**写到 `_系统/日志/工作项统计/` 内，也不要散落在仓库根目录。开始查询前先创建：

```bash
mkdir -p "${HOME}/pp-note/.tmp"
TMP_DIR="$(mktemp -d "${HOME}/pp-note/.tmp/云效工作项统计.XXXXXX")"
```

`$TMP_DIR` 仅用于本次运行的过程产物，第 6 步会整体清理。

### 第 2 步：逐项目获取时间范围内的工作项

调用 `search_workitems`，按公共说明传项目与类别参数，时间筛选用 `updatedAfter/updatedBefore`，从第 1 页开始逐页获取。

日期筛选对应原来的 `--date-field gmtModified`。按完整北京时间范围在本地复核 `gmtModified`，按工作项 ID 去重，原始与中间数据仅写入本次 `$TMP_DIR`。分页上限与拆分规则使用公共说明，不能遗漏分页。

### 第 3 步：按既有统计口径分类

本统计技能原有月报/周报的“待办”是仅 `todo`，不同于工作项管理技能一般查询的 `todo+doing`。迁移不静默改变历史口径，报告中明确“待办仅 todo”；用户明确要求所有未完成时，纳入 `doing` 并在报告中标注。

按返回的 `status.nameEn/name/displayName` 与公共说明中的状态映射分类。不要把 `todo/done` 填入 MCP 的状态 ID 参数；未能识别的状态不得直接算入待办或完成，应说明覆盖缺口。

“已完成”仍指时间范围内有更新、当前处于 done 的工作项，不代表在该时段完成的事件数；只有用户明确要求完成时间统计时，才核实并使用 `finishTimeAfter/finishTimeBefore` 或状态变更历史，更新报告口径。

### 第 4 步：数据处理

1. **排除人员**（除非用户明确要求包含）：
   - 排除名单从 `_系统/技能数据/待办事项排除人员.md` 读取，不再硬编码。该文件每行格式为「分类：姓名、姓名、姓名」（如「负责人：罗宇辉、顾宝程」「产品经理：蒋鹏」「已离职：李莎仕」）。
   - 解析方式：逐行取「：」（或半角 `:`）之后的内容，按「、」「，」`,` 分隔得到姓名，去除空白后汇总为排除集合；忽略空行与无「：」的行。
   - 若该文件不存在或为空，则不做排除（全部纳入统计）。
   - 该排除动作仅作为内部数据处理逻辑；输出文档、摘要和给用户的回复中不要体现排除规则、排除名单、排除前后数量，除非用户明确追问排除口径。

2. **按负责人分组统计**：
   - 待办数量
   - 已完成数量
   - 合计

3. **待办明细按负责人分组排序**（数量降序）

### 第 5 步：生成文档

保存到笔记库 `~/pp-note` 下的 `_系统/日志/工作项统计/工作项统计 YYYY-MM-DD.md`（使用当天日期）。

如果目录不存在，自动创建。

最终 Markdown 报告必须包含完整待办明细和必要统计，不能依赖额外 CSV/JSON 文件才能阅读。

### 第 6 步：清理过程产物

生成并校验 Markdown 报告后，整体删除临时目录，仅保留 Markdown 报告：

```bash
rm -rf "$TMP_DIR"
```

由于所有过程产物（raw JSON、中间 JSON、CSV、summary JSON、`.err`/`.tmp` 等）都在笔记库本次运行的 `$TMP_DIR` 内，仅删除本次创建的 `$TMP_DIR` 即可清理干净，不会误删 `_系统/日志/工作项统计/` 下的报告。

只有用户明确要求保留 CSV、raw JSON 或 summary JSON 时，才保留对应文件——此时将其从本次 `$TMP_DIR` 移动到 `_系统/日志/工作项统计/` 根目录再删除本次 `$TMP_DIR`，并在回复中说明保留原因。

## 输出文档结构

### Frontmatter

```yaml
---
title: 云效工作项统计
date: YYYY-MM-DD
tags:
  - 云效
  - 工作项
  - 统计
type: output
query_range: "YYYY-MM-DD ~ YYYY-MM-DD"
---
```

### 文档正文

```markdown
# 云效工作项统计（YYYY-MM-DD ~ YYYY-MM-DD）

> 查询条件：最近 N 个月/周有更新的工作项，按更新时间过滤；待办仅 todo，已完成为当前 done 状态。

## 总览

| 负责人 | 待办 | 已完成 | 合计 |
|--------|------|--------|------|
| 张三   | 10   | 20     | 30   |
| ...    | ...  | ...    | ...  |
| **合计** | **N** | **N** | **N** |

## 按项目统计

| 项目 | 待办 | 过期 |
|------|------|------|
| 项目 A | 10 | 2 |
| ... | ... | ... |

---

## 待办明细

### 张三（N 条）

| 编号 | 标题 | 类型 | 优先级 | 计划完成 | 项目 | 更新时间 |
|------|------|------|--------|----------|------|----------|
| [XXX-123](链接) | 标题 | 任务 | 高 | 2026-05-01 | 项目名 | 04-29 |

### 李四（N 条）

...

---

> 本文档由智能体生成于 YYYY-MM-DD，数据来源：云效官方 MCP；本次运行的临时 CSV/JSON 过程产物已清理。
```

### 明细字段映射

| 文档字段 | 数据来源 |
|----------|---------|
| 编号 | `serialNumber`，带链接 |
| 标题 | `subject` |
| 类型 | `workitemType.name` |
| 优先级 | `customFieldValues` 中 `fieldId` 为 `priority` 或 `fieldName` 为"优先级"，取 `values[].displayValue` |
| 计划完成 | 优先 `dueDate`/`planFinishTime`/`plannedFinishTime`/`expectedFinishTime`；否则查 `customFieldValues` 中包含"计划完成""截止""到期"的字段 |
| 项目 | `space.name` |
| 更新时间 | `gmtModified`，格式 `MM-DD` |

### 链接生成

优先使用返回数据中的 `detailUrl`、`webUrl` 或 `url`；如果接口未返回链接，用以下格式生成：

```
https://devops.aliyun.com/projex/project/<space.id>/<category-route>/<id>
```

`category-route` 按 `categoryId` 映射：`Req` → `req`，`Task` → `task`，`Bug` → `bug`，其他值使用小写形式。

## 汇报要求

执行完成后，在对话中展示：

1. **统计摘要**：总览表（人员 × 待办/已完成/合计）
2. **关键发现**：
   - 待办积压最多的人员
   - 完成量最高的人员
   - 其他值得关注的模式（如某项目集中爆发等）
3. **文档位置**：告知用户 Markdown 报告已保存的路径（wikilink 格式）
4. **清理结果**：说明本次运行的 CSV、raw JSON、summary JSON 过程产物已删除；不要把已删除文件作为可点击结果返回。

## 停止条件

- 官方 MCP 未接入、组织无法确定或必要接口无权限
- 项目 ID 无法确定（环境变量与 `_系统/技能数据/云效关注项目.md` 均为空）
- API 返回权限不足或查询失败
- 用户要求包含被排除人员时，跳过排除逻辑；输出文档和回复仍不要额外说明排除口径

## 示例对话

用户：帮我统计一下工作项（默认最近 1 个月）
用户：工作项月报（最近 1 个月）
用户：工作项周报（最近 1 周）
用户：统计待办（默认最近 1 个月）
用户：统计最近一周的工作项（最近 1 周）

执行流程：
1. 发现官方 MCP 工具，确认组织与项目范围
2. 构建项目 ID 列表（环境变量 + `_系统/技能数据/云效关注项目.md` 去重）
3. 计算时间范围
4. 逐项目分页查询（`spaceId`），按现有状态口径分类待办与已完成
5. 按 `_系统/技能数据/待办事项排除人员.md` 排除人员，按人员分组
6. 生成文档到 `_系统/日志/工作项统计/`
7. 校验 Markdown 报告包含完整明细
8. 删除本次 `$TMP_DIR` 临时目录（含 raw JSON、CSV、summary JSON 等全部过程产物）
9. 展示统计摘要和 Markdown 报告位置
